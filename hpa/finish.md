## 📊 性能调优与架构复盘

回顾一下你在本次演练中完成的云原生最佳实践：

### 1. 基础设施即代码 (IaC)
*   你摒弃了快捷的命令行方式，选择**声明式地编写 HPA YAML 清单**。
*   这遵循了企业级的 GitOps 最佳实践，确保了扩缩容策略可以被版本控制、审计追踪以及跨环境复现，避免了手动操作带来的配置漂移。

### 2. 资源利用与成本控制
*   你设置了 **`minReplicas: 1`**：保证在没有流量的闲时，系统只保留最基础的 1 个副本，极大节省了云服务器的闲置成本。
*   你设置了 **`maxReplicas: 4`**：在大促洪峰时，设定了资源上限。这能防止因突发异常流量导致无限扩容，保护了集群的整体稳定性。
*   你设置了 **`50%`** 的 CPU 阈值：这是一个极其经典的“黄金比例”，既能快速响应流量变化，又不会因为轻微的指标抖动导致频繁的 Pod 启停（脑裂）。

### 3. 压力测试与指标观测
*   你学会了如何使用 Busybox 发起持续 HTTP 请求制造压力。
*   你掌握了 `kubectl get hpa -w` 命令，并理解了 Metrics Server 采集数据存在 **1-2 分钟的延迟**，这是 K8s 指标监控的常态。

💡 **生产环境进阶建议**：
在真实的复杂业务中，仅靠 CPU 扩容可能不够。你可以尝试引入 **KEDA (Kubernetes Event-driven Autoscaling)**，基于消息队列长度（如 Kafka 积压）或 QPS 指标来进行更精准、更实时的自动扩缩容。
