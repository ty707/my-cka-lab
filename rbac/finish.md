## 📝 安全架构复盘

回顾一下你的安全收敛操作：

1. **身份隔离**：通过创建专用的 `ServiceAccount`，避免了多个应用共享默认高权限账号的风险。
2. **权限精细化**：你配置的 `Role` 严格限定了 Verbs（`get`、`list`、`watch`），彻底剥夺了删除或修改核心资源的权限。
3. **自动化校验**：后台的 `kubectl auth can-i` 验证逻辑，等同于模拟黑客视角的“红蓝对抗”测试，证明你的权限配置确实生效。

💡 **生产环境进阶建议**：
在复杂的微服务架构中，建议引入 **OPA (Open Policy Agent)** 或 **Kyverno**，在 API Server 准入阶段实施更复杂的准入控制策略（Admission Control），拦截任何不符合安全规范的 YAML 提交。
